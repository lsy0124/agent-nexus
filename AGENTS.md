# Agent Nexus development rules

- Only create and modify files inside this project. Put scratch data and caches in `work/`, user-facing reports in `outputs/`.
- Never read another agent's credentials, authentication files, cookies, tokens or private client data. Do not reverse engineer clients.
- No global installs, Windows configuration changes, third-party Skill installation, remote Git pushes or external messaging without explicit user authorization.
- Never invent Agent connectivity, execution results, task completions, performance numbers or approval decisions. Installation discovery and real request verification are separate states.
- Phase 3 preserves the verified Codex bridge and adds independently gated official adapters. Gemini prefers its isolated official Google subscription CLI; REST requires separately supplied memory-only keys and explicit account/cost approval. WorkBuddy OAuth is read-only onboarding, never execution permission. Models generate text plans; Nexus validates and writes in a generated Git Worktree. Generic shell, hooks, plugins, browser tools, system changes, dependency installation by an Agent, deletion and remote pushes remain disabled.
- Ordinary automated tests must not invoke real models. Real Codex browser acceptance requires explicit `NEXUS_LIVE_CODEX=1`; use the existing official CLI login without reading or copying its credential files.
- Skill candidates are inert text. Static review is heuristic; manifest validation is not code execution or proof of safety. Approval records do not activate executable capabilities.
- Use `.venv/Scripts/python.exe`, `frontend/node_modules`, project-local caches and the checked-in dependency locks.
- Run `scripts/test.ps1` after relevant implementation changes. Run `.venv/Scripts/python.exe scripts/browser_test.py` for frontend integration changes; it uses an isolated test database and an existing browser.
- Launcher entry points (`scripts/console.ps1`, the desktop shortcut's target) are read by Windows PowerShell 5.1. Any `.ps1` containing non-ASCII text must stay UTF-8 **with BOM**, or 5.1 decodes it with the local code page and fails to parse. `backend/tests/test_launcher_encoding.py` enforces this; many editors drop the BOM silently.
- `frontend/tests/e2e.mjs` creates and executes tasks. It refuses to run without `NEXUS_URL`, so use `npm --prefix frontend run test:e2e` (isolated instance on port 5173). Never point it at the normal console on 8765: that writes test tasks into the user's database.
- Console list endpoints (`/api/state`, `/api/tasks`) must stay O(runtimes + rows): batch per-task facts in one query instead of opening a connection or probing an adapter per task.
- Do not change or remove a user's tasks or database as test cleanup. Browser QA uses `work/browser-qa/`.
- Worktree paths and branch names must remain generated by the backend and confined to `work/worktrees/`. Worktrees are code isolation, not an OS sandbox.
- Phase 4 adds a unified Agent/model/provider plane (`catalog.py`), a usage collector (`usage.py`), a quota interface (`quota.py`) and a budget guard (`budget.py`). Keep four facts apart: a **declaration** (catalog), a **verification** (a real request was made), a **provider-reported** number, and a **Nexus estimate**. Never render one as another.
- `usage_source` must stay honest: only a usage object the provider actually returned is `provider-reported`. Streaming usage counts only when the provider sends a final usage chunk; `STREAMING_USAGE_VERIFIED` starts empty and is filled by observation, never by assumption. A request without reported usage is recorded with NULL token columns and counted only as a call.
- Costs are always labelled as estimates with a `cost_source`. Never substitute one provider's published price for another provider's route, and never treat "unpriceable" as "free".
- Quota results carry their `kind` and are never summed across `official_account_balance`, `third_party_gateway_balance`, `nexus_budget` and `subscription_allowance`. Do not guess a private balance endpoint, scrape login cookies or bypass a provider's authorization.
- API keys live only in the backend. The API may return a fingerprint and a length, never the key or a readable fragment. The default vault is memory-only; the DPAPI backend is opt-in and must report its fallback loudly. Never log an `Authorization` header.
- Real API acceptance (`scripts/real_api_acceptance.py --live`) consumes the user's metered quota and requires explicitly supplied keys. Ordinary tests must never reach a real model.
